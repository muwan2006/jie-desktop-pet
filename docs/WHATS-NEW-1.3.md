# 1.3.0：累计功能更新与操作流程

本版同步完整版 1.43.0 的程序能力。公开版单独编号；基础程序使用独立资料目录，不包含作者的账号、群聊、授权令牌、收藏、训练资料或本机模型。功能包从九项增加到十项。

## 一、老用户怎么更新

1. 从托盘或桌宠右键菜单选择「退出桌宠」。关闭设置窗口不等于退出。
2. 在 [1.3.0 发布页](https://github.com/muwan2006/jie-desktop-pet/releases/tag/v1.3.0) 下载 `Jie-Community-Repair-1.3.0.zip`，完整解压。
3. 双击「更新桌宠.cmd」，选择你原来的基础版 `Jie.exe`。适用于公开版 1.0.0 至 1.2.5；不能用于作者完整版。
4. 等待校验和备份完成，重新打开原来的程序。
5. 打开「功能中心」，刷新目录，将「QQ聊天」更新到 **1.2.3**；其他已安装包按页面提示更新即可。「唱歌与翻唱」是新增的可选包。
6. 功能包安装成功会退出并重新打开一次。检查安装数量和对应页面。更新期间不要手动反复启动。
7. 原资料、接口配置和聊天记录保留。若程序文件曾自行修改，更新器会停止覆盖并说明文件名；先保留现有目录，不要强行删除资料。

新用户下载完整基础版 ZIP，完整解压，运行 `Jie.exe`，在功能中心勾选需要的包。基本聊天先配置自己的模型；详见[完整指南](USER_GUIDE.zh-CN.md)。

## 二、QQ连接与群设置

1. 安装「QQ聊天」，打开「颉的QQ」，在顶部连接区选择 NapCat 或 LLBot。独立桥接需要按其官方要求安装、登录专用QQ号和完成授权。
2. 展开「账号与桥接配置」填写主人QQ号、称呼、实际的 OneBot WebSocket 地址与密钥。LLBot启动授权令牌与OneBot密钥是不同设置。
3. 保存设置，点击一次「连接QQ」，等待启动、登录检查与账号核对完成。需要扫码或安全验证时按提示完成，不要反复点击启动。
4. 在好友与群管理中授权需要参与的会话。进入某个群的设置，可单独指定角色卡、接话偏好和相关开关；不指定时沿用颉的角色卡。
5. 如果多个QQ窗口同时登录，按页面提示绑定机器人的窗口，避免连接主人号。平台限制、未完成扫码和错误令牌仍需人工处理；重试不会解除账号限制。

连接与发送记录、常用接入入口已调整到更方便查看的位置。连接恢复使用状态检查和退避；不会因为一次连接失败反复操作QQ窗口。

## 三、对话和表达方式

1. 在「回复与主动接话／对话偏好」分别设置群聊和私聊的详细度。
2. 允许群内自然接话后，调整最短间隔和百分比概率。间隔到期只是允许尝试，仍需有新话题和适合回应的内容。
3. 支持根据当前表达选择文字、单语音、单表情或组合。先装「声音与朗读」并配置可用TTS，才能实际发送语音；表情需在收藏中可用。
4. 日常相邻对话默认直接发送，仅在需要明确回复对象或区分旧消息时引用。模型与上下文会影响实际选择，不保证固定比例出现某种形式。
5. 自然接话优先当前话题，过旧消息不会仅因进入历史上下文而重新被当作新问题回复。
6. 在表情收藏中可删除默认表情，并管理自行收藏的表情；不同角色可选择适合自己的素材。

## 四、记忆、每日复盘与统一的自己

1. 群里由设置中的主人号 **真实@她，并包含「记住」**；主人私聊直接说「记住……」。文字资料、习惯、群梗、识图纠错共用这个入口。其他群友不能直接改写主人确认资料。
2. 在「对话与会话记忆」「会话资料」查看、编辑或删除对应会话的记录；群与好友各自保存原始对话。长记录分层保留近期原文、摘要、事件和归档，检索仍可能漏掉内容，不等同于无限上下文。
3. 「每日复盘」默认每天 **17:00（本机时间）**，可修改时间；也可点击「立即复盘今天」。需程序运行、连接可用，空闲时处理；暂停后不再自动应用本群调整。
4. 复盘可从真实消息和反馈提出新的表达经验，经证据检查后应用。页面可查看来源、撤销、恢复和暂停；没有人回应不等于得到负面评价。它改变的是保存的记忆与表达策略，**不是重新训练聊天模型权重**。
5. 在「统一的自己」查看共享经验和回顾设置。去掉个人、群名和具体事件后的通用表达经验可以用于其他会话；原群角色卡与原始记忆仍独立。
6. 主人私聊和桌宠本地聊天可以按授权召回群中经历，回应「最近群里有什么趣事」等问题，也可适度分享经历。群聊提示词不会直接收到其他群或主人私聊的原文；删除和撤回仍应在来源会话处理。

## 五、发图片、看视频、转发记录

1. 打开QQ中的「图片与视频／图库」设置，添加本地图片文件夹，可修改路径、补充描述并添加图片。
2. 说「发一张某角色的图片」，优先从已配置图库寻找；不够时按配置使用联网找图与候选核对。无可靠结果会说明未找到，不会拿无关图冒充。
3. 图片识别与联网搜索是不同能力。主聊天模型需要支持图片，或配置适合的识图链路；只开启搜索并不会让纯文本模型直接看图。
4. 群中主动识图默认不强制以图搜图，不确定时可以不接话；被@明确要求识图时按相关开关核对，不能确认就说明不知道。联网回复默认隐藏来源链接，明确索要时再给。
5. 直接发送QQ视频，或发送B站／抖音视频链接，可请求「看看这个视频」。解码、转写需「本地识别与文档组件」，视觉理解仍需可用图片模型。可说「从01:20开始看」「继续看」「查看视频摘要」。
6. 支持展开读取合并转发的聊天记录，再按是否有必要决定回复。来源中无法取得的附件不会被当成已经看过。
7. 她自己分享过的视频保留阅读笔记；接着讨论通常复用笔记。只有新的观看要求或缺少内容时才继续获取，不会把每句感想都重新当成看视频任务。
8. 图片、视频和网站受网络、登录权限、地区和平台接口影响；B站或抖音链接不保证每条都能读取。Cookie只在本机配置，不要发到群里。

## 六、自主看B站和阅读成长

1. 在QQ页「B站阅读」中启用相关功能，填写感兴趣的话题、频率与分享设置。
2. 需要可用模型、网络和本地识别组件；读取公开候选视频时记录实际看过的范围，不把标题、封面或评论当成已经看完整片。
3. 当前自动候选以短视频为主，有长度与处理预算限制；不是登录个人账号无限刷推荐流。
4. 在阅读记录中查看笔记、来源和成长条目，可停止、删除或停用。分享只发给已配置的主人会话；不自动对外发评论、投稿或操作B站账号。
5. 阅读所得可形成有来源、可修订和可遗忘的认识；表达经验可以纳入整体学习。单个视频观点不被自动确认为事实，任务也可能因处理失败而没有形成新认识。

## 七、下棋与Codex项目

1. 群里@她说「下五子棋」「下围棋」或「下象棋」。三类棋使用独立对局，可以分别进行；同一种棋仍需明确当前对局与落子对象。
2. 说「简单」「普通」「困难」「挑战」切换对应难度。象棋重新分档，新困难和挑战使用更高搜索预算，思考时间可能更长。
3. 发起者可结束自己的棋局；设置中的主人可在群里@她发送结束该类棋局的指令，解除发起者离线后占着棋局的情况。其他人不能随意结束别人的棋局。
4. 主人私聊QQ可接续已授权Codex项目：先在QQ页项目设置中同步本机Codex列表并绑定已有聊天，再说「在某项目里……」。需本机Codex单独登录并运行；不要将聊天模型API当作Codex项目执行账号。
5. 手机QQ可先分开发图片／文件，再发送任务文字。查看收到的附件和任务确认；只在已授权项目、主人会话内提交。不要因为没有同步立刻重复发任务。
6. 可询问任务进度、取消任务；完成后按要求回传成果图片或文件。遇到Codex自己的审批应在Codex处理。QQ远程任务不绕过项目权限和本机审批。

## 八、唱歌与翻唱（独立准备引擎）

1. 在功能中心安装「唱歌与翻唱」，其界面依赖「声音与朗读」「记录与效率」。这是控制与处理代码包，**不包含SoulX大模型、CUDA、Python歌声环境或个人训练权重**。
2. 按 [歌声引擎说明](SINGING.md) 准备完整引擎目录和参考音频，再进入「小工具 → 唱歌与翻唱歌库 → 歌声组件与播放设置」选择目录。界面会检查组件是否齐全。
3. 输入「歌名 歌手」在线搜歌，选择「唱这个版本」。首次制作需取得完整音源、分离、转换和混音，依硬件耗时。
4. 完成后手动播放或导出WAV；QQ私聊可说「点歌 歌名 歌手」，群里真实@她点歌。做好后以QQ语音回传，长曲分段发送；QQ语音处理另需本地音视频组件。
5. 音源不可用、只有试听或组件不完整时会提示失败。没有配置引擎时不会假装已唱好，也不会用普通TTS朗读歌词代替。

其他入口的逐步配置见[完整指南](USER_GUIDE.zh-CN.md)、[QQ接入](QQ.md)、[API设置](API-SERVICES.md)和[故障排查](TROUBLESHOOTING.md)。
